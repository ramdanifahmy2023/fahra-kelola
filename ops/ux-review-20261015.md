# UI/UX follow-up implementation

15 October 2026. Implements the approved [audit plan](../anti-slop/audit-001-2026-10-15.md) in `codex/ux-improvements-20261015`, with combined Finance/HPP verification in a separate detached worktree. User authorized merging and pushing to `main` after checks pass.

## Result and contracts

- Dashboard keeps sales, attention items, and fund positions visible. Store ledgers are a native disclosure; its summary retains reconciliation differences and shops requiring review. Hash links open the correct disclosure. Existing source/pending disclosures and filter-preserving Finance links remain.
- Products, Orders, and Customers use a compact shared recap. Useful stock/order actions, missing-data warnings, and scope stay visible; metrics, trends, and full breakdowns remain under “Rincian & grafik”. Long product names use two lines in the list and are fully accessible in the existing keyboard dialog. SKU and variants have an explicit disclosure. Null stock stays unknown. Pagination wraps at 320px.
- “Ambil data Shopee” requests upstream refresh on operational pages; “Muat ulang data” reads saved data. Dashboard's narrower “Perbarui saldo Shopee” label remains accurate. Ads and topup scopes are independent. The report field `confirmed_orders` is labelled “Pesanan terkonfirmasi”, consistent with the source and Dashboard, not the shipping/completed order status.
- Reports retains nullable values in summary and chart APIs. Each metric has `coverage.current/previous[metric] = {known_days, expected_days, complete}` on rows and totals. Total expected days count every selected shop, including shops without snapshots. Partial sums remain visible with a label; all-unknown sums stay null. Growth needs complete GMV in both periods and a positive comparison denominator. Conversion needs complete orders and UV and positive UV. A selected shop with no data remains visible; account scoping is preserved.
- Comparison dates retain the existing contract: the first day of the selected month through the end date, compared with the same number of immediately preceding days. The UI shows both actual ranges rather than claiming matching calendar dates last month. Missing chart dates break lines. Numeric daily values are available, including unknown dates. Mobile ranking cards prioritize the selected sort metric; details remain available without horizontal table navigation.
- Report requests reject late responses and hide prior content when filters change or fail. Shop selection restores keyboard focus. Sidebar links are at least 44px; group labels use readable theme colors.

## Concurrent Finance/HPP work

At task start, main had 12 uncommitted Finance/HPP/config/documentation files. Their original bytes and hashes were backed up under ignored `tmp/main-backup`. Backend Finance/HPP and configuration changes are not part of this UI commit.

The optional P&L UI is provided by `templates/finance-profit.php`, `finance-profit.js`, and `report-snapshot.js`. The existing Finance loader initializes `profitView` only when its panel exists. In the concurrent P&L branch, render the shared PHP fragment into `$financeProfitPanel` and delegate its existing loader to:

```js
async function loadProfitLoss() {
  return profitView?.load({...applied, basis:profitBasis});
}
```

The combined checkout and main's preserved working changes use this adapter. Do not restore the old `renderProfitLoss` implementation when committing that feature. Keep the existing basis/tab/filter handlers, endpoint, HPP links, and backend calculations. The base UI commit does not enable a P&L endpoint that is absent from its baseline.

Snapshot identity includes shop IDs, start/end dates, and basis. Changing it clears old figures immediately, including failed requests and reverting to a prior basis. Same-scope refresh failures may retain the last successful data with an explicit message. Older responses cannot overwrite current results. Open details and link/summary focus survive successful polling updates. The compact P&L summary keeps missing HPP, revenue coverage, missing ad coverage, and the limitation on net profit visible.

## Design review

UI UX Pro Max mobile-table guidance was applied to Reports and checked against the project's existing selectors and data semantics. Antislop used throughout and in final review: ENERGY 1 / RHYTHM 2 / MOTION 1. Warm Shopdash surfaces, orange actions and tabular monetary figures remain. Disclosures serve daily scan speed; warnings remain visible. Native controls and explicit detail paths preserve keyboard/touch access. No invented metrics, decorative charts, new fonts, gradients, or animation were added.
